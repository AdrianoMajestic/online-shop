# Пояснительная записка: Задача T00. Каркас проекта

## Что сделано
- Инициализирован проект на Next.js 14+ (App Router) с React 18 и TypeScript strict.
- Проект полностью переведен на пакетный менеджер **pnpm** (`pnpm-lock.yaml`, `pnpm-workspace.yaml`).
- Настроены Tailwind CSS, shadcn/ui, ESLint, Prettier, Vitest, скрипты `pnpm dev`, `build`, `typecheck`, `lint`, `test`, `seed`.
- Созданы базовые модули `src/lib/db.ts` (кэшированное Mongoose-подключение), `src/lib/errors.ts` (типизированные API ошибки), главная страница с `Header` и `Footer`, и роут `/api/health`.
- Создана документация: `docs/TZ.md`, `docs/TZ_ISSUES.md`, `docs/DECISIONS.md` (включая D-005 о pnpm), `docs/TRACEABILITY.md`, `docs/ER.md`.

## Почему именно так
- Использование pnpm исключает phantom dependencies и ускоряет сборку за счет content-addressable хранилища.
- Кэширование Mongoose (`global.mongooseCache`) предотвращает исчерпание пула соединений при HMR в Next.js.
- Централизованный `handleError` в `lib/errors.ts` обеспечивает соответствие единому API-формату `{ error: { code, message, details } }`.
- Vitest изолированно тестирует чистую бизнес-логику без оверхеда браузерного окружения.

## Ключевые файлы
- `src/lib/db.ts` — кэшированное подключение к MongoDB через Mongoose 8.
- `src/lib/errors.ts` — иерархия классов ошибок (`AppError`) и обработчик Route Handlers.
- `src/app/api/health/route.ts` — эндпоинт проверки статуса сервера и реального подключения к БД.
- `src/app/page.tsx`, `src/components/Header.tsx`, `src/components/Footer.tsx` — базовая страница с шапкой и футером.
- `docs/DECISIONS.md`, `docs/TZ_ISSUES.md`, `docs/TRACEABILITY.md` — базовая документация и аудит ТЗ.

## 3 вопроса для защиты с ответами
1. **Зачем кэшировать Mongoose-соединение в глобальном объекте в `lib/db.ts`?**
   *Ответ:* В режиме разработки Next.js при hot-reload модули пересоздаются. Без кэширования в `global` каждый запрос или перезагрузка создавали бы новое соединение к MongoDB, быстро исчерпав лимит пула (на Atlas M0 лимит 500).
2. **Почему в проекте выбрана MongoDB вместо PostgreSQL, указанного в исходном ТЗ?**
   *Ответ:* Решение зафиксировано в D-001: гибридная модель MongoDB позволяет хранить неизменяемые снимки товаров, цен и адресов прямо в документе заказа без сложных внешних ключей, исключая риск мутации исторических данных.
3. **Как обеспечивается единообразие обработки ошибок во всех Route Handlers?**
   *Ответ:* Через класс `AppError` и функцию `handleError`, которая перехватывает `AppError`, ошибки валидации `ZodError` и стандартные исключения, форматируя их в согласованный JSON-ответ с соответствующим HTTP-кодом.
