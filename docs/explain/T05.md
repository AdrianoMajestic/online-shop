# Пояснительная записка: Задача T05. Корзина

## Что сделано
- **Хранение корзины:** для гостя — в `localStorage` браузера (ключ `kabachok_cart`, строго массив `{ productId, quantity }` без цен); для авторизованного пользователя — в MongoDB через модель `Cart` (`userId`, `items: [{ productId, quantity }]`).
- **Серверные API Route Handlers:** `GET /api/cart` (получение серверной корзины с актуальными ценами и остатками), `PUT /api/cart` (обновление корзины с серверной валидацией остатков или флагом слияния), `DELETE /api/cart` (очистка корзины), `POST /api/cart/details` (публичный эндпоинт обогащения гостевой корзины актуальными ценами без сохранения в БД), `POST /api/cart/merge` (явное слияние корзин).
- **Слияние корзин:** при входе (`/login`) или регистрации (`/register`), а также при изменении сессии в `CartProvider`, товары из `localStorage` объединяются с корзиной в БД. Одинаковые товары суммируются, но их суммарное количество строго ограничивается физическим остатком `Math.min(sum, stockQuantity)`. Товары с нулевым остатком отсекаются. После успешного слияния `localStorage` полностью очищается.
- **Серверный контроль цен и остатков:** цены и скидки берутся исключительно из MongoDB по `productId`. При попытке установить количество больше физического остатка (`stockQuantity`) сервер возвращает ошибку 409 `ConflictError` с кодом `OUT_OF_STOCK`.
- **UI корзины:** иконка со динамическим счётчиком количества товаров в хедере (`Header.tsx`), интерактивная страница `/cart` со степпером количества, удалением позиций, расчётом промежуточной суммы и экономии, а также блоком рекомендаций хитов продаж при пустой корзине.

## Почему именно так
- Согласно разделу 2, 4 и 6 `AGENT_SPEC.md` и решению D-011, цены и складские остатки рассчитываются исключительно на сервере: клиентские данные (`localStorage`) содержат только идентификаторы и количество, что полностью исключает подделку стоимости покупателем.
- Гостевая корзина не засоряет базу данных фантомными сессиями (допущение A-14), а слияние при входе обеспечивает бесшовный UX: покупатель не теряет собранный заказ после авторизации.
- Поле `userId` в схеме `Cart` сделано полиморфным (`Schema.Types.Mixed`), что предотвращает `CastError` при сохранении 32-символьных строковых ID Better Auth.

## Ключевые файлы
- `src/models/Cart.ts` — Mongoose-модель корзины авторизованного пользователя (`userId`, `items`).
- `src/services/cart.service.ts` — бизнес-логика: обогащение цен, слияние корзин, серверная валидация остатков `OUT_OF_STOCK`.
- `src/app/api/cart/route.ts` — эндпоинты `GET`, `PUT`, `DELETE /api/cart` для авторизованных пользователей.
- `src/app/api/cart/details/route.ts` — эндпоинт `POST /api/cart/details` для подтягивания актуальных цен гостевой корзины.
- `src/app/api/cart/merge/route.ts` — эндпоинт `POST /api/cart/merge` для слияния гостевой и серверной корзин.
- `src/lib/cart-context.tsx` — глобальный React-контекст `CartProvider` и хук `useCart()` для синхронизации состояния.
- `src/components/Header.tsx` — динамический бейдж количества товаров в шапке.
- `src/app/cart/page.tsx` и `src/components/CartContent.tsx` — страница корзины и блок рекомендаций.
- `src/tests/cart.test.ts` — unit-тесты бизнес-логики, валидации, слияния, проверки остатков и API роутов.

## 3 вопроса для защиты с ответами
1. **Почему цены товаров не хранятся в `localStorage` для гостевой корзины и как отображается их стоимость на странице `/cart`?**
   *Ответ:* Хранение цен на клиенте в `localStorage` создает критическую уязвимость: пользователь может вручную отредактировать цену в DevTools, либо цена в каталоге изменится администратором, породив рассинхронизацию. Поэтому в `localStorage` хранятся только `{ productId, quantity }`. При загрузке страницы корзины клиент вызывает эндпоинт `POST /api/cart/details`, сервер загружает актуальные цены и скидки из MongoDB и возвращает обогащенную структуру без записи в базу данных.
2. **Как работает механизм слияния корзин при входе и что происходит, если суммарное количество превышает остаток на складе?**
   *Ответ:* При успешном входе или регистрации клиент передает сохраненный массив гостевых товаров на сервер. Метод `mergeGuestCart` находит товары пользователя в MongoDB, группирует одинаковые `productId` и суммирует количества. Затем сервер проверяет текущий физический остаток каждого товара `stockQuantity`: итоговое количество ограничивается `Math.min(sumQuantity, stockQuantity)`. Товары с нулевым остатком удаляются. Сервер сохраняет результат в БД, возвращает обновленную корзину, а клиент очищает `localStorage`.
3. **Где и как реализована проверка на превышение остатка товара на складе?**
   *Ответ:* Проверка выполняется строго на сервере в `cart.service.ts` (`updateUserCart`). Если клиент пытается передать количество больше, чем `product.stockQuantity`, сервер не применяет изменения и выбрасывает исключение `ConflictError` с HTTP-статусом 409 и кодом `OUT_OF_STOCK`, передавая в `details` доступный остаток. На клиенте кнопка увеличения количества также блокируется по известному остатку, предотвращая невалидные запросы на уровне UI.
